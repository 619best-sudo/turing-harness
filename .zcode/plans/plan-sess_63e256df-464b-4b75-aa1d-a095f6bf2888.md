# Plan: Complete the media_analysis → write/edit → inspiration pipeline

## Your clarified intent (the simple if/else)

For UI development only (`ui`/`svg` writes):
- **Image attached** → use `media_analysis` to categorize it (UI replica vs OCR vs other). If UI replica → pass image directly to write/edit vision authoring with a replication prompt. If OCR-like → just use its content. No synthesis.
- **No image** → harness auto-calls `inspiration_generator` (the TOOL) and uses its JSON as `designReference`.
- **No image, no inspiration match** → load a design SKILL as final fallback.
- All paths reach the authoring model with *some* reference; never blind.
- `media_analysis` gets a full content-hash cache (mirroring comprehension).

## What currently exists (built for the OPPOSITE case — must be removed/inverted)

- `design-reference-synthesis.ts` — fires **only when an image IS present**, synthesizing a structured reference *from* it. Plus `tests/design-reference-synthesis.test.mjs` (229 lines, 11 tests).
- `loop.ts:700-773` — the trigger gate `canAuthor && !designReference?.length && callImageCount > 0 && isUiOrSvgPath(argPath)`.
- `media-analysis-reuse.ts` — a UI-sliver cache only (`lens:"ui"`, single image); explicitly "out of scope" for the general case.
- `media-analysis.ts:644-647` — records UI analyses into that sliver.

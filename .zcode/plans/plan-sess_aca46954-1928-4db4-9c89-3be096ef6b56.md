## Activity Monitor — Trace/Debug Workflow (Revised)

### Core Flow
```
Agent instruments code → code runs (manual or auto) → agent collects logs → reasons
```

### New/Enhanced Actions

**1. `action: "instrument"`** — Start a trace session
- Generates unique `traceId` (e.g., `turing-trace-x7k2m9p1`)
- Returns ready-to-paste logging snippets for the target language
- Snippets write to BOTH `console.log` AND `/tmp/<traceId>.log` (file-based capture)
- Parameters:
  - `language` — auto-detected from project files if omitted
  - `runMode` — `"manual"` (default) or `"auto"`
  - `startCommand` — e.g., `"npm run dev"` (only when `runMode: "auto"`)
  - `port` — kill existing process on this port before restart (only when `runMode: "auto"`)
  - `hint` — optional trace purpose hint

**`runMode: "manual"`** (default):
- Agent adds `__trace()` calls → tells user "Run your app"
- User runs normally, output shows in terminal + writes to trace file

**`runMode: "auto"`**:
- Agent adds `__trace()` calls → tool kills old process on `port`, restarts with `startCommand`
- Stdout/stderr piped to trace file + returned to agent
- Returns PID so agent can stop later via `cleanup`

**2. `action: "collect"`** — Read trace results
- Reads `/tmp/<traceId>.log`, returns timestamped ordered lines
- Optionally passes through study model for AI analysis
- Parameters: `traceId`, `analyze` (boolean)

**3. `action: "cleanup"`** — Tear down
- Deletes `/tmp/<traceId>.log`
- If auto-started: kills the dev server PID
- Returns instrumented file list so agent can remove `__trace()` calls
- Parameters: `traceId`

**4. `action: "inspect"`** — UI/debugging inspection (NEW)
- For frontend/mobile UI issues: navigate to a page/component and capture state
- Parameters:
  - `traceId` — filter console logs by this ID
  - `url` — target page URL (e.g., `http://localhost:3000/dashboard`)
  - `mode` — `"console"` (get console logs), `"screenshot"` (capture page), `"full"` (both)
  - `selector` — optional CSS selector to screenshot a specific component
  - `analyze` — pass screenshot to study model for alignment/UI analysis
- Uses existing Playwright MCP tools or mobile MCP (if registered) under the hood — will resolve from the registry at runtime
- Falls back gracefully if no browser automation MCP is available

### Implementation

**File: `src/tools/builtin/activity-monitor.ts`**
- Add `instrument`, `collect`, `cleanup`, `inspect` to the existing tool's `action` enum
- Keep existing `search`, `tags`, `tail_file`, `study` unchanged
- For `inspect`: resolve Playwright/mobile MCP tools from `ctx.registry` at runtime; graceful fallback if unavailable

### Example Flows

**Flow A — Backend debugging (manual):**
```
Agent: activity_monitor {action:"instrument", runMode:"manual"}
       → traceId + code snippets
Agent: edits code with __trace() calls
Agent: "Please run your server and trigger the flow"
User:  runs app → logs in terminal + trace file
Agent: activity_monitor {action:"collect", traceId:"...", analyze:true}
       → timestamped flow + AI analysis
Agent: activity_monitor {action:"cleanup", traceId:"..."}
```

**Flow B — Frontend debugging (auto):**
```
Agent: activity_monitor {action:"instrument", runMode:"auto", startCommand:"npm run dev", port:3000}
       → restarts server, returns traceId + snippets + PID
Agent: edits code with __trace() calls (auto-reload picks them up)
Agent: activity_monitor {action:"inspect", url:"http://localhost:3000", traceId:"...", mode:"full", selector:".header", analyze:true}
       → navigates to page, captures console logs + component screenshot + AI UI analysis
Agent: "The header component is misaligned by 8px..."
Agent: activity_monitor {action:"cleanup", traceId:"..."} → kills server, deletes trace file
```

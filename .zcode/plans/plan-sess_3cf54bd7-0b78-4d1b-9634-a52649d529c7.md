# turing-harness v2 — The Categorizer (final)

Small-model-friendly orchestration: a router picks one focused **categorizer** (small toolset + combined prompt + **its own orchestrator model**); each runs a fresh scoped tool loop, ends via a terminal `deliver` tool, then the router picks the next from its children — or `summarise`. Client signature unchanged.

## Per your two refinements
1. **Per-categorizer orchestrator model**: `CategorizerDefinition.model?` (slug) + optional `reasoning` — "which model does this categorizer's reasoning". Resolution order: categorizer's `model` → role-slot default (conversation→`prepare` slot, read/write_edit/activity_inspect→`perform` slot) → `DEFAULT_PHASE_MODELS`. Router runs on `setup.routerModel ?? prepare slot`; summary turn on `perfect` slot. The chain switches driver models as it enters/exits each categorizer. Runtime override: `orchestrator.setModel(target, slug)` accepts categorizer ids.
2. **write/edit works current way only**: Model-B authoring, `routeModel({kind:"write",rating,category,hasAttachment,path})`, `authorOnlyWrites`, staged-read escalation, `declaredComplexity`/`declaredCategory`, image floor, plan-task + tool-measured complexity floors, `selectModel`, permission `model`/`authorModel`/`thinkingLevel` — all preserved verbatim and threaded into every categorizer loop (also for other internally-escalating tools: media_analysis, create_plan, activity_study).

## New `src/categorizer/`
- `types.ts` — `CategorizerDefinition {id, name, description, systemPrompt, tools[], children[], accepts{from[],tools[]}, returns{kind,description,deliverSchema?}, model?, reasoning?, entry?, maxSteps?}`, `CategorizerSetup {categories, globalTools, routerModel?, doubtModel?, maxHops?}`, `CategorizerHop`, deliverable types (`summary`/`code-summary`/`write-report`/`inspect-report`).
- `guidance.ts` — topic guidance blocks moved from `phases/prompts.ts` (COMPLEXITY_CONTRACT, FILE_SEARCH_LADDER, DEBUGGING_LOOP, etc.), tool-gated selection kept.
- `prompts.ts` — the four default combined prompts (tool-gated guidance), router prompt, `buildCategorizerSystemPrompt(def, toolNames, opts)`.
- `setup.ts` — `defineCategorizer`, `createCategorizerSetup` (validates ids/children/accepts/entry), `DEFAULT_CATEGORIZER_SETUP`:
  | id | tools | children | accepts | returns |
  |---|---|---|---|---|
  | conversation | — (globals) | [] | fresh | summary |
  | read | read/ls/grep/bash_readonly/mark_concern_lines/*_memory | write_edit, activity_inspect | fresh | files + linked codeSummary (line numbers + snippets), optional memoryUpdates |
  | write_edit | write/edit/**create_plan always**/assets_generator/inspiration_generator/design_skill | activity_inspect | read + activity_inspect deliverables | writes report |
  | activity_inspect | activity_*/add_log/remove_log/media_analysis/mobile | write_edit | write_edit deliverable + write/edit tool results | writes echo + logPaths + findings + bugLocation + verdict |
  Globals for ALL: bash, ask_user_question, clearing_doubt, web_search, web_fetch, web_scrape (+ mention-resolved MCP/skill tools).
- `deliver.ts` — terminal `deliver` tool from `returns` schema; `AgentTool.terminal` ends the loop; fallback deliverable derived if model stops without calling it.
- `clearing-doubt.ts` — available everywhere; consults big model (`setup.doubtModel ?? orchestrator slot ?? tencent/hy3`) → returns numbered steps executed with the categorizer's own tools.
- `mentions.ts` — parse `/skill` + `#mcp|#file` from prompt; resolved provider tools added to every categorizer.
- `router.ts` — one cheap tool-free LLM call: task + attachments + mentions + compact chain state → `CATEGORY: <id>|summarise`; choices rendered with each category's description/prompt/returns; heuristic fallback; bug prompts bias read→activity_inspect; `verify:false` discourages post-write inspect.
- `chain.ts` — driver: mentions → attachment triage → router → scoped `runToolLoop` (per-categorizer model, fresh first call, accepted-context-only openings) → deliverable → events `categorizer_start/end` → pause on pending question → hop cap (6, no immediate repeat) → probe-strip cleanup → summary turn → `RunLoopResult` (steps from write_edit plan + writtenPaths, `verified` from inspect verdict, threadSnapshot).

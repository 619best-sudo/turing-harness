# Plan: Enforced verification + run-handoff (amended for flawless OpenWaggleMain classic-run compatibility)

## Goal
Make "verify what you wrote" **binding** in the flat `run()` loop, with the build → ask-who-runs-it → drive-or-wait handoff. Two gates: the existing pre-fix `ReproductionGate` (unchanged) + a new post-dev `VerificationGate`. The hard requirement is **flawless compatibility** with OpenWaggleMain's `classic-run` (Turing model path through `agent.prompt`).

## How OpenWaggleMain consumes the harness (the constraints)
Found via `/Users/shashankv/Projects/OpenWaggleMain` exploration — these shape every decision below:

- **`agent.prompt(prompt, attachments, { planMode })` is the ONLY entrypoint** (`turing-classic-run.ts:959`). The host never calls `run()`/`runChain()`/`runPhase()` directly. → The verification phase lives **inside `run()`**, transparent to the host.
- **Host reads `agent.state`, not `RunLoopResult`** post-run: `lastRunSummary`, `lastSteps`, `lastPlanSet`, `lastThreadSnapshot`, `pendingUserQuestion`, `error`. → Verification surfaces through `lastThreadSnapshot.verified` + a new `lastVerification` state field. New `RunLoopResult` fields are additive (ignored by host, safe).
- **`ThreadRunSnapshot.verified` already exists and is read by the host** (`turing-run-classification.ts:98`) but the flat `run()` never populates it. → My gate **fills** it via `buildRunThreadSnapshot`. This is a fix, not a break.
- **`AskUserQuestionRequest.phase` is typed `'prepare'|'plan'|'perform'|'perfect'` on the host** (`user-question.ts:18`), part of the resolve-match key, and renderer-keyed. → The run-handoff question uses **`phase: 'perfect'`** (in the union, semantically correct). **No new phase value, no host-side type change.**
- **`isBugFix` is already derived by the host** via `describesRuntimeSymptom(input.payload.text)` (`turing-classic-run.ts:545`). → **Drop the planned auto-hint** (it was redundant; would conflict). The pre-fix gate stays exactly as-is.
- **The `askUserQuestion` callback returns a bare `string`**; the run-handoff calls it the same way the model would. Inline-blocking works because the host installs the callback always (`turing-classic-run.ts:856`).
- **`ThreadRunSnapshot` core fields + `disposition` enum are load-bearing for cross-run persistence** (`isThreadRunSnapshot` validates them). → I add only `verified` (already on the type) and never touch the core fields or enum.

## Iron rule: verification is non-fatal
Every new code path wraps in try/catch and degrades to "skip verification, report `verified: false` honestly." If the verification loop errors, if no surfaces are connected, if the user picks "skip," or if `maxRounds` is hit — the run still completes normally. **A verification failure never fails a run that would otherwise succeed.** This is what "flawless" means here.

## Architecture — 3 new modules + integration (gate is on by default, host can disable)

### 1. NEW `src/orchestrator/verification-gate.ts`
Mirrors `reproduction-gate.ts` structure. Pure state machine, no I/O — fully unit-testable.

**Per-written-path state:**
```ts
{ path, diff?, tier?: "runtime"|"static", method?: "visual"|"logic"|"endpoint"|"none",
  reason?, hasEvidence: boolean, evidenceTool?, declaredAt?: number }
```

**Methods:**
- `observeWritten(path, diff?)` — on every successful write/edit. **Re-writing resets `hasEvidence`** (edit-after-verify ⇒ re-verify).
- `observeCheck(toolName, isError, outputChars, refs?)` — on every successful tool result. `activity_inspect` (non-empty + has image block), `activity_collect`/`activity_study` (non-empty), `media_analysis` with `VERDICT: PASS` in output, `bash` carrying a passing test/build → set `hasEvidence` on paths currently owed verification with a matching declared method. MCP-prefix-tolerant (`mobile-mcp__activity_inspect`).
- `declare(declarations)` — records the model's per-file `{path, tier, method, reason}`. This **is** the "ask yourself: visual/logs/nothing" step, made binding. `none`/`static` with a reason = auditable bypass; `visual`/`logic`/`endpoint` = evidence required.
- `isSatisfied()` / `gaps()` (path + method + diff excerpt, for the verify-loop message) / `toReport()` (`{checked, certified, unverified}`).
- **Tier fallback heuristic** (only when the model never declares): `UI_EXTENSIONS` (reused from `coding.ts`) → `visual`; code exts → `logic`; `.md/.json/.yaml`/fixtures → `static`. Declaration is authoritative when present, so a model that doesn't declare still gets useful gating.

### 2. NEW `src/orchestrator/run-handoff.ts`
`coordinateRunHandoff({registry, askUserQuestion, writtenPaths, declaredMethods, runId, evidenceDir, signal})` → `Promise<HandoffResult>`. All wrapped in try/catch → `mode: "skip"` on any error.

**Flow:**
1. `detectSurfaces(registry)` → `{browser, mobile}` (reuses the candidate-name lists from `activity-monitor.ts:547-570`, extracted to a shared helper).
2. **Needed only if** some written file declared `visual`/`endpoint` (a running app is required). Pure-logic/static runs → **no prompt at all** (respects "not all files need testing").
3. When needed, call `askUserQuestion` directly (orchestrator-side, inline-blocking, `phase: 'perfect'`) with 3 options:
   - **"You run it"** (recommended when a surface MCP is connected) → agent drives in the verify loop.
   - **"I'll run it"** → run blocks; user drops log/screenshot at `evidenceDir`; returns the path; gate treats `activity_tail_file`/`media_analysis file:<path>` as evidence.
   - **"Skip verification"** → gate records unverified, run proceeds.
4. `askUserQuestion` absent → `mode: "skip"` (no deadlock; surfaces used opportunistically, rest reported unverified).

Returns `{mode: 'agent'|'user'|'skip', surfaces, evidenceDir, userEvidencePath?}`.

### 3. NEW `src/orchestrator/verify-artifacts.ts` (~40 lines)
`runArtifactDir(cwd, runId)` → `.turing/verify/<runId>/` (`.turing/` already gitignored in both repos); `writeEvidence` / `listEvidence`. `runId = run-<Date.now()>-<4hex>`, generated once in `run()`. Existing `os.tmpdir()` trace paths untouched (back-compat).

### 5. MODIFY `src/orchestrator/orchestrator.ts` (`run()`, L911-1193) — the core change
- **~L950:** `const runId = 'run-${Date.now()}-${rnd}'`; `const verificationGate = (!opts.verify || opts.verify !== false) ? new VerificationGate({runId, cwd, maxRounds}) : undefined`. Default ON.
- Thread `verificationGate` into planning `runToolLoop` (L979) and each work `runToolLoop` (L1065).
- **NEW verification phase, between L1152 (end of work loops) and L1155 (summary), entirely guarded:**
  ```
  let verified: boolean | undefined;
  if (verificationGate && writtenPaths.length && !pendingUserQuestion && !signal?.aborted) {
    try {
      const handoff = await coordinateRunHandoff({...});            // may inline-block on askUserQuestion
      if (handoff.mode !== "skip") {
        for (let round = 0; round < maxRounds && !verificationGate.isSatisfied() && !signal?.aborted; round++) {
          const gaps = verificationGate.gaps();
          const verifyLoop = await runToolLoop({
            ..., priorMessages: carryMessages,
            userMessage: buildVerificationMessage(gaps, handoff, verificationGate.toReport()),
            label: `verify-${round}`,
          });
          carryMessages = verifyLoop.messages;
          collectLoopPaths(writtenPaths, ...);   // a fix during verify still counts
          pendingUserQuestion = pendingUserQuestion ?? verifyLoop.pendingUserQuestion;
        }
      }
      verified = verificationGate.isSatisfied();
    } catch {
      verified = false;   // NON-FATAL: never fail the run over verification
    }
  }
  ```
- `buildVerificationMessage` emits: gap list (path + method + diff excerpt), routes (visual → `activity_inspect selector:<from diff>` + `media_analysis lens:qa expected:<from diff>`; logic → trace loop or project tests; endpoint → `curl`), handoff result (evidence path if user drove), and the declaration format.
- **`buildRunThreadSnapshot` (L2300):** add `verified?: boolean` to input, spread it (`...(typeof input.verified === "boolean" ? { verified: input.verified } : {})`). Pass `verified` from the flat-run call site (L1165). ← This is the seam that makes verification visible to OpenWaggleMain with **zero host change**.
- **`summarizeRun` (L1381):** accept `verificationReport`; add a `VERIFICATION:` block to the prompt so the summary is grounded in gate state (replacing the current "mention a check ONLY if the report says it was run"). Non-fatal if report is absent.
- Return `verified` on `RunLoopResult` (L1180 block).

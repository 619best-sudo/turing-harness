## Goal — write/edit only, keeping author-first
Keep the existing author-model contract (the driver NEVER authors `newString`/`content`; the author model writes the bytes — as OpenWaggle already runs with `AUTHOR_ONLY_WRITES=true`). Make `write`/`edit` consume the comprehension reasoning so the weak driver uses them efficiently, and fix the root cause of "the last run edited everything via `bash`."

## Root cause (verified in code)
The harness ships `authorOnlyBashTool` + `detectShellAuthoring`, which refuses source mutations via `bash` — but it splits each command on newlines. The run's mutations were multi-line:
- `sed -i '' '218a\  <newline> …' lib/services/auth_service.dart` — the `sed` segment is cut at the newline, so the `… file` path lands in a *different* segment with no `sed`.
- `python3 << 'EOF' <newline> … open('lib/…','w')` — the `open(...,'w')` write sits on a later line, so `python3 … open(` never co-occur in one segment.

So every `sed -i`/python-write slipped past the guard (which existed but was structurally blind to multi-line/heredoc forms), letting the weak driver author files through `bash`.

## Part 1 — Fix the bash-edit root cause (harness, `coding.ts`)
- **Rework `detectShellAuthoring` to be shell/heredoc-aware**: extract heredoc blocks (`cmd << 'EOF'` … terminator) as single units and check the whole unit for content-authoring forms; split non-heredoc commands on `&&`/`;`/`|` only (respecting quotes), never on newlines inside continuations/heredocs. This closes the exact gap — catches `sed -i` multi-line and `python3` heredoc `open(…,'w')`/`Path(…).write_text` to `AUTHORED_EXTENSIONS` paths, while builds/git/reads/log-redirects stay untouched.
- **Prompt**: add to the write_edit prompt an explicit rule — "Do NOT modify source files via bash (sed/perl/redirection/python rewrites). All file changes go through `write`/`edit`; `bash` is for build/test/lint/git and read-only inspection."

## Part 2 — write/edit consume the comprehension (author-first, `coding.ts`)
- **`edit` anchor leniency (3 safe tiers)**: exact match (unchanged) → whitespace/indentation-normalized match (collapse `[ \t]+` runs + strip line-trailing whitespace) with correct byte-span mapping back to the original file, applied only when unique → otherwise miss. This absorbs the weak driver's indentation imprecision so its edits land instead of erroring.
- **`edit` miss-resolution via comprehension**: on a miss, use `recallComprehensionFor(ctx, file)` + the file's bytes to return a **resolving diagnostic** — the closest matching region's exact bytes + line, and the comprehension's relevant note — so the driver re-issues ONE correct `edit` (never `sed`).
- **Vend + keep comprehension**: when `write`/`edit` targets a comprehended file, the result notes that the whole-file expert analysis is already in the run and, on a miss, shows the exact bytes; the AUTHOR model continues to receive the comprehension (`priorRead.analysis` → `authorFileContent`/`authorEditReplacement`) and writes the replacement. Driver-authored `newString`/`content` is unchanged (absent under author-only / never authored by the driver).

## Part 3 — Tests (existing offline scripted-bridge style)
- `detectShellAuthoring`: catches **multi-line `sed -i … file`**, **`python3 << heredoc` with `open(…,'w')` to a source path**, and `Path(…).write_text` heredocs; still allows builds (`flutter build`), reads (`cat … | head`), and `git diff`.
- `edit`: whitespace/indent-lenient anchor applies via correct byte mapping; a genuine miss returns the resolving diagnostic with exact bytes; author-only flow unchanged (author model writes the replacement from the comprehension).
- write_edit prompt text contains the bash-source-mutation prohibition.
- `npm run build && npm test` (all suites green).

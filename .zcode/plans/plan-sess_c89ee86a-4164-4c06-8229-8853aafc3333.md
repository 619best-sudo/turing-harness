# Enforced activity-inspect verification loop (build → logs → verifier → verify → strip | repair) + debugging parity

## Context (from last-run inspection of `OpenWaggleMain/.openwaggle-user-data-dev/openwaggle.db`, session `b63e36eb`)

The last run ("change title of delete account popup", cards_mobile_app) shows the gap: after the `edit`, the model spent 20+ tool calls freestyle-driving the simulator inside the **work loop** (mobile clicks / screenshots, fighting a `GestureDetector` + pixel-ratio math), declared done, argued against verification, and only ran `activity_inspect` / `remove_log` / `activity_cleanup` at the very end. No build stage, no FAIL→repair cycle ever fired.

The harness already has most of the machinery — `VerifyStageTracker` (`instrument → run → inspect → decide`), `VerificationGate`, `QaGate` (scope/freshness/build-target refusals), strip round, `maxRounds=5`/`maxAttempts=2` budgets. What's missing is exactly the flow you described:

1. **No structural `build` stage** — build discipline is only prompt text inside the `run` slice + refusal messages.
2. **No explicit "not verified → edit/write again" transition** — verify rounds *permit* edits, but nothing resets the spine to `build` after a fix, and no FAIL signal drives a repair round.
3. **Debugging runs reuse the same spine but without collect/study wording or a fix→re-verify→strip/revert contract in the stage messages.**

## Changes

### 1. Add a `build` stage to the verify spine — `src/orchestrator/verify-stages.ts`

- `VerifyStage = "build" | "instrument" | "run" | "inspect" | "decide"`.
- New `buildSlice` message: quotes the detected `deviceCommands` / `webCommands` (already passed as `VerifyStageContext`), instructs build+install with `background: true` + log polling, and states that captures are refused until it lands (QaGate already enforces the refusal half).
- `VerifyStageTracker`:
  - Track write/build ordering: `onWritten()` (existing) sets `needsBuild = true` when the project has build-relevant commands; new `onBuildOk()` clears it.
  - New `noteFailure(reasons)` — records an explicit verification FAIL for the next round's framing.
  - `stage()` update: if gaps need runtime evidence AND `needsBuild` AND build commands exist → return `"build"` **before** the instrument check (endpoint-only/curl gaps and static-logic gaps keep skipping to `run`/`inspect` as today; last-round `decide` forcing unchanged).
- Build-success observation — `src/orchestrator/loop.ts` (next to the existing `verifyStageTracker.onCapture` hook ~line 1578): on a non-error `bash` result whose command `classify()`es as build/install/run (reuse `src/exec/run-commands.ts` `classify` + detected run commands) or a ready `activity_trace_start`, call `stageTracker.onBuildOk()`. Same hook in `phase-runner.ts` if it threads the tracker.

### 2. FAIL → repair transition (the "if not verified → run edit/write again" loop)

- In `src/orchestrator/orchestrator.ts` verify loop (~1880–1900), after each round: parse `VERDICT: FAIL` (and failing gaps from `verificationGate.gaps()`) from `verifyLoop.finalText` → `stageTracker.noteFailure(...)`.
- `buildStageMessage` gains a repair preamble when the tracker recorded a failure: list the failing gaps + observed failure reasons, explicitly authorize `edit`/`write` to fix, and state that after the fix the spine restarts at `build` (stage selection does this automatically via `needsBuild` from `onWritten`).
- Budgets unchanged (`maxRounds`/`maxAttempts` bound the loop — "until whole run completes" stays honest: budget exhaustion still completes with `verified: false`, never an infinite loop).

### 3. Debugging parity (same spine for bug-fix runs)

- Thread `isBugFix` into `buildStageMessage` context; when true:
  - `build`/`run` slices use `DEBUGGING_LOOP` wording (prompts.ts:126) — reproduce-first already enforced by `ReproductionGate` before the first edit.
  - `inspect` slice instructs `activity_collect` + `activity_study` on the trace (log evidence), not just screenshot inspection.
  - `decide` slice gets the debug contract: **fixed → `remove_log` + `activity_cleanup` → done; not fixed → revert the fix (or keep probes), re-edit, spine restarts at `build`.**
- Strip round already runs unconditionally after the loop (orchestrator.ts:1942–1997) — verified it covers failed attempts too.

### 4. Tests + docs

- `tests/` (follow existing `*.test.mjs` node:test style): stage progression `build → instrument → run → inspect → decide`; write mid-spine resets to `build`; endpoint-only gap skips build+instrument; `noteFailure` produces repair framing; `blockPrematureStrip` unchanged; build-ok observation from classified bash results.
- Update `docs/qa-sequence.md` (build becomes a structural stage, repair loop documented), `docs/loop.md`, `docs/debugging.md` (spine parity section).

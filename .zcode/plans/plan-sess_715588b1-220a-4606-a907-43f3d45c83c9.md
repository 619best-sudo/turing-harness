## Goal
When `inspiration_generator` (or the design-skill fallback) produces section blueprints for a fresh UI build, the harness should **auto-generate the image/video/audio assets those blueprints call for** and thread their paths into authoring — so the write embeds real assets instead of leaving placeholders or authoring blind. (Currently this chaining is prompt-only; the harness never calls `assets_generator` from inspiration output.)

Your note that all backends are wired in the `OPenWaggleMain` app means image/video/audio all produce real assets in your environment; where a backend is absent the tool already returns a flagged placeholder, so the auto-call is safe regardless.

## Scope gate (already in code)
This only fires inside the existing `isFreshUiBuild` block (loop.ts:833): a `write` to a NEW UI/SVG file, no reference image, non-backend project — i.e. exactly "creating a new UI from scratch with no design of your own." Not every run.

## Implementation

### 1. New helper: `src/orchestrator/asset-generation.ts`
- `MediaNeed = { kind: "image"|"video"|"audio"; role: string; prompt: string }`
- `GeneratedAsset = { path: string; kind: "image"|"video"|"audio"; role: string }`
- **`extractMediaNeeds(sections: unknown[]): MediaNeed[]`** — scan each section's `elements[]`; for each element, read its `role`/`type`/`kind` (case-insensitive) and classify:
  - **image**: tokens `image|photo|picture|illustration|thumbnail|hero-image|product-image|background-image` (NOT `icon`/`logo` — those are project-specific, not generatable)
  - **video**: `video|background-video|cinemagraph|clip|movie` (NOT `animation` — that's the motion spec, not an asset)
  - **audio**: `audio|sound|music|voiceover|narration|soundtrack`
  - Build a generation `prompt` from the matched role + the section's `name`/`description`/`category` + the run task + any aspect ratio on the element. Dedup by `kind+role`; cap at ~8 needs.
- **`generateAssetsFromReference({ sections, task, registry, cwd, llm, logStore, signal }): Promise<GeneratedAsset[]>`** — resolve `assets_generator` from the registry (skip → `[]` if absent); for each need, call `tool.execute(id, { kind, prompt, name }, ctx)`; collect `details.files[].path` into `GeneratedAsset[]`. Resilient: per-need try/catch; a failure skips that need, never the build.

### 2. `src/types.ts`
- Add `generatedAssets?: GeneratedAsset[]` to `AuthoringContext` (mirror `designReference`/`mediaFact`).

### 3. `src/tools/builtin/authoring.ts`
- Add `generatedAssets?` to `AuthorFileContentInput` and `AuthorEditReplacementInput`.
- Render in BOTH `buildWriteUserMessage` (:615) and `buildEditUserMessage` (:654): a block `GENERATED ASSETS (the harness generated these from the design reference — embed these paths for their roles; replace any flagged PLACEHOLDER with a real file before shipping):\n<role> (<kind>): <path> …`.

### 4. `src/tools/builtin/coding.ts`
- Forward `ctx.authoringContext?.generatedAssets` into the authoring input at both sites (:1352 write, :1611 edit), mirroring the `designReference` line.

### 5. `src/orchestrator/loop.ts`
- Declare `let generatedAssets: GeneratedAsset[] | undefined` alongside `designReference`.
- After the reference ladder completes inside `if (!fileExists)` (after rung 3, ~:929), call `generateAssetsFromReference({ sections: designReference, task: refTask, registry, cwd, llm, logStore, signal })`; set `generatedAssets`; log it (`inspiration → generated N asset(s)`); fold its `usage` in.
- Thread into the authoring context assembly (~:970): `...(generatedAssets?.length ? { generatedAssets } : {})`.

## Problem
After a write finishes, the verify phase is one fat message + a free tool loop. It routes visual changes to screenshot-only (no logs), has no "wait for the app to run" state for the user-driven handoff, and never enforces a decide step — so the model scatters (the `cards_mobile_app` run: 50 turns of mobile-mcp flailing, never saw its own change). The handoff question (`coordinateRunHandoff`) exists; the structured flow *after* it does not.

## Goal — one backbone serving all three modes
- **QA (user-run):** handoff → instrument → **WAIT for user** → inspect → decide
- **Debugging:** reproduce-first (existing ReproductionGate) → fix → instrument → run → inspect → decide (FAIL → re-reproduce)
- **Development:** build → instrument → run → inspect → decide (+ visual compare)

Common spine: **instrument (`add_log`) → run/wait → inspect (`activity_collect`/`study` ± visual) → decide (pass / reproduce / fix)**. Logs become the backbone for *all* runtime changes including visual; visual capture is a complement, not a substitute.

## Implementation

### 1. NEW `src/orchestrator/verify-stages.ts`
- `VerifyStage = "instrument" | "run" | "inspect" | "decide"`.
- `VerifyStageTracker`: holds the gaps; tracks per-gap `instrumented`/`captured`/`verdict`; `stage()` derives the current stage; `observe(toolName, details)` advances from the **same loop signals already plumbed** — `add_log`→`details.instrumented` (loop.ts:1350), `activity_collect`/`activity_inspect`/`activity_study`/`media_analysis`→captured (loop.ts:1373). Gaps removed by a static/`none` DECLARE drop out, so satisfied gaps are skipped automatically.
- `buildStageMessage(stage, ctx)`: a **focused one-stage** message (not all stages at once — this is the anti-scatter fix). Every stage message keeps the `"VERIFY WHAT YOU WROTE"` header anchor + round counter (test detection). Body per stage:
  - **instrument**: open trace (`activity_trace_start`) + `add_log` on the changed lines of each runtime gap; "logs required even for visual"; agent→then run; user→then STOP and wait. DECLARE-none still available for genuinely trivial changes.
  - **run** (agent): run the app (`<deviceCommand>`/`<devServer>`) + `activity_collect {traceId, waitMs}`.
  - **run/wait** (user): "the user is running the app; reading dropped evidence next" (orchestrator wait runs between rounds).
  - **inspect**: `activity_collect`/`activity_study`; visual gaps ALSO `activity_inspect {expected}`/`media_analysis lens:'qa'`; "read where the trail stops."
  - **decide**: commit VERIFIED (cite the evidence line) or FAIL→(bug-fix? reproduce : fix+re-verify); then `remove_log`/`activity_cleanup`.

### 2. NEW `src/orchestrator/evidence-wait.ts`
- `waitForUserEvidence({ dir, userEvidencePath, deadlineMs, signal, onProgress })`: bounded poll (1.5s tick, mirroring `activity_collect.waitMs`) of the evidence dir for new files / the named path; emits progress ("waiting for the user to run the app…"); returns files appeared (or `[]` on timeout). Non-fatal, abort-aware.

### 3. `src/orchestrator/orchestrator.ts` verify loop (1618–1743) refactor
- Build a `VerifyStageTracker` from `gaps()` + `handoff.mode`.
- Replace `buildVerificationMessage(...)` with `buildStageMessage(tracker.stage(), ...)`.
- **User-mode wait:** when `mode==="user"` and the tracker advances to "run" after instrumentation, call `waitForUserEvidence(...)` before the next round (bounded, with progress). Agent-mode: no orchestrator wait — the run-stage message drives `activity_collect.waitMs`.
- Bump `maxRounds` default 3→5 (instrument/run/inspect/decide + a fix round); still configurable, not asserted by tests.
- Preserve exactly: `runToolLoop` options (systemPrompt, images, mediaFact, projectCategory, gates), DECLARE parsing (`parseDeclarations`), `verifyEndedEarly` recording, non-fatal try/catch, `isSatisfied()` termination, probe-strip block afterward.

### 4. `src/orchestrator/run-handoff.ts`
- Ensure `evidenceDir` is populated for user-mode (already receives `verifyEvidenceDir`). No change to the question itself.

### 5. `src/orchestrator/verification-gate.ts` — **unchanged**
- Instrumentation is a *stage* signal (tracker), not gate evidence. The gate still accepts collect/study→logic, inspect-PASS/media-PASS→visual, bash-pass→logic/endpoint. This keeps the DECLARE-static bypass intact (gaps empty → no staged rounds → `verified:true`), preserving the `.md`/static tests.

## Invariants preserved (existing test contracts)
- `"VERIFY WHAT YOU WROTE"` anchor kept in every stage message (`verify-loop-context`, `verification-integration` detect the verify turn by it).
- Static/`none`-DECLARE bypass short-circuits — no instrumentation forced on static/trivial changes.
- `verify:false` disables everything.
- `runToolLoop` context (images/mediaFact/category/systemPrompt) unchanged.
- Non-fatal: any throw → `verified:false`, run still succeeds.

## Tests
- Update: `verify-loop-context.test.mjs`, `verification-integration.test.mjs` (stage messages carry the anchor; DECLARE-static still bypasses; negative path still `verified:false`).
- New `verify-stages.test.mjs`: stage derivation from observations; instrument→run→inspect→decide transitions; user-mode triggers the evidence wait; agent-mode run-stage uses `collect.waitMs`; FAIL→reproduce on a bug-fix decide.
- New `evidence-wait.test.mjs`: bounded poll returns appeared files; timeout→`[]` non-fatal; abort respected.

## How each mode is served (concretely)
- **QA / user-run:** handoff "I'll run it myself" → agent instruments (`activity_trace_start` opens the localhost collector + `add_log` inserts `__t()`) → orchestrator waits on evidenceDir → user runs the app (probes POST to the collector → trace file grows) and/or drops a screenshot → inspect (`activity_collect`/`activity_tail_file`/`media_analysis`) → decide.
- **Debugging:** ReproductionGate already forces capture-before-fix in the work loop; the verify loop's decide-FAIL routes back to reproduce. Same spine, observed before (repro) and after (verify).
- **Development:** build → instrument → run (agent) → inspect (logs + visual compare) → decide.

## Scope / risk
Core change = verify loop + two small new modules; gate logic untouched; behavior for static/declarative changes unchanged. Main risk is stage budget vs rounds — mitigated by bumping `maxRounds` and letting the gate report an honest `unverified` if budget exhausts. Build target is `dist/` (the tests import from `../dist/index.js`), so the plan ends with a `tsc` build + full `npm test`.

## Goal (OpenWaggleMain renderer)

In the phase timeline, change how `read` / `write` / `edit` results render:
- **Read**: always expanded, fixed-height scrollable line-numbered view, with the concern lines (from `mark_concern_lines`) highlighted.
- **Write/Edit**: always expanded, with green/red diff lines (edit already has this via `UnifiedDiffView`), the action label (WRITE/EDIT) + `+N -M` badges grouped on the right of the header.
- **`mark_concern_lines`**: NOT shown as its own row — its `{ path, lines, why }` is consumed silently to highlight the matching read's lines.

## Scope

**Only the Phase timeline path** (`PhaseTimelineCard` + `ToolCallBlockParts` + `tool-call-block.ts`). The `AssistantMessageBubble` inline path is header-only for every tool and out of scope (no expanded body exists there; the file/diff views only render in the timeline).

## Key facts driving the design

- `mark_concern_lines` results already arrive at the renderer opaquely inside `tool.toolResult.content` → `details: { path, lines, why }`. No IPC/transport changes.
- `read` result `details.path` and `mark_concern_lines` `details.path` are both resolved absolute paths → correlate by exact match.
- Harness `readTool` output embeds line numbers as `"<n>\t<line>"`, so the view can show accurate numbers even for `offset` reads.
- `StreamingText`/shiki can't do per-line backgrounds → need a new line-based renderer. Syntax highlighting is sacrificed for read results in exchange for accurate line numbers + concern highlights (acceptable: the renderer already drops shiki for large files via `shouldHighlightCode`).

## Files to change

### 1. `src/renderer/src/features/chat/lib/tool-call-block.ts`
- Add type + accessor: `getConcernLinesFromResult(content): { path: string; lines: number[]; why?: string } | null` — reads `details.path` (string) + `details.lines` (number[]) via `getToolResultDetails`.
- Add `splitNumberedFileLines(content): { number: number; text: string }[]` — splits on `\n`; for each line strips an optional leading `<digits>\t` (harness format); `number` = the embedded number when present, else the 1-based index. Empty trailing line dropped.
- Export a `READ_VIEW_MAX_HEIGHT_PX = 320` constant (reuse for read + write views).

### 2. `src/renderer/src/features/chat/components/ToolCallBlockParts.tsx`
- Add `FileContentView({ lines, concernSet, variant, maxHeight })`:
  - Renders a fixed-height (`maxHeight`, overflow-y-auto) monospaced column.
  - Each row: a right-aligned line-number gutter + the line text.
  - `variant: 'default' | 'additions'`:
    - `default` (read): concern lines get a left accent bar + subtle highlight bg (`bg-amber-400/10` + `border-l-2 border-amber-400/60`) and a slightly bolder gutter number; non-concern lines plain.
    - `additions` (write): every line green-tinted (`bg-success/5`, gutter number green) — treats written content as all-added, matching "green lines" for write.
  - Large-file guard: if line count exceeds a threshold (e.g. 2000), fall back to the existing plain `<pre>` (keep responsiveness).
- Update `ToolResult`'s `name === 'read'` branch to render `<FileContentView lines={splitNumberedFileLines(displayContent)} concernSet={concernSet} variant="default" maxHeight={READ_VIEW_MAX_HEIGHT_PX} />`. Add an optional `concernLines?: Set<number>` prop threaded from the card.

### 3. `src/renderer/src/features/chat/components/PhaseTimelineCard.tsx`
- **Header layout (write/edit)**: move the action chip (`WRITE`/`EDIT`) to the **right** of the file path, grouped with the existing `+N -M` badges — i.e. `[path ...] [WRITE/EDIT chip] [+N -M]` on the right; remove the left action chip for write/edit (keep `READ` chip on the left for reads, unchanged).
- **Default expand**: change `const [expanded, setExpanded] = useState(false)` to initialize `true` when `hasExpandableDetails` AND tool is `read`/`write`/`edit` — `useState(hasExpandableDetails && ['read','write','edit'].includes(tool.toolName))`.
- **Pass concern lines to read**: in `ToolStrip`, accept a `concernLines?: number[]` prop; build a `Set` and pass to `<ToolResult concernLines={...} />` in the read branch.
- **Write content as additions view**: in the write/edit expanded branch, for `write` render the `args.content` via `<FileContentView variant="additions" ...>` (instead of / above `ToolArgs`); for `edit` keep `<UnifiedDiffView>` (already green/red).
- **Hide mark_concern_lines + build concerns map**: in `PhaseTimelineCard` (the section that maps `phase.tools`), before rendering:
  - Collect `concernsByPath: Map<string, { lines: number[]; why?: string }>` from every tool whose `toolName === 'mark_concern_lines'` and whose result yields concern data (via `getConcernLinesFromResult`), keyed by `details.path`.
  - Filter `mark_concern_lines` tools OUT of the rendered list.
  - For each remaining tool, derive its resolved path (from `tool.toolResult` details `.path` for reads; fall back to `parseToolPath(args)`) and look up `concernsByPath.get(path)` → pass as `concernLines` to `ToolStrip`.

### 4. No changes to
- `AssistantMessageBubble.tsx` (inline path — header only, out of scope).
- IPC / preload / transport types / stream reducer (`details` already flows opaquely).
- Shared types (`mark_concern_lines` result is already reachable as opaque `JsonValue`).

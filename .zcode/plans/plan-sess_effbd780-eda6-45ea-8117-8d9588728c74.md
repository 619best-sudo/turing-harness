## Goal

When a permission callback returns `decision.authorModel = "<model-b>"` on a `write`/`edit` call, **Model B authors the bytes that hit disk**, from scratch. Model A's draft (`content` / `newString`) is discarded for `write`; for `edit`, Model A's `oldString` is kept as the anchor and Model B authors the replacement. Today's `decision.model` semantics ("B processes the result") are left untouched — `authorModel` is a sibling field, fully backward-compatible.

This respects the runner's design invariant (`phase-runner.ts:1-11`: "the orchestrator/runner never reasons over file contents … all reasoning is done by the phase model, all IO/mutation by tools") by having the **tool** make the Model B call — exactly the established pattern in `src/tools/builtin/ui-screen-auditor.ts` and `activity-monitor.ts` (`ctx.llm.complete(...)` + `ctx.model`).

## Why it must be the tool, not the runner

By the time the permission callback fires (`phase-runner.ts:924`), Model A has already committed its args one full turn earlier (`:674`). The only structural way for Model B to author is an internal LLM call *inside* the tool's `execute`, before `fs.writeFile`. The runner's job stays limited to: resolve `decision.authorModel` → thread it + authoring context into `toolCtx` → accumulate the resulting usage.

## Changes

### 1. Types — `src/types.ts`

- **`PermissionDecision`** (~line 808, sibling to `model`): add
  ```ts
  /**
   * OpenRouter slug of the model that should AUTHOR the bytes for a mutating
   * write/edit call (Model B), instead of using the requesting model's (Model A's)
   * draft content. Model B authors from scratch: given the path, task, plan, and
   * surrounding file context, it produces the file content (write) or the
   * replacement text (edit — Model A's `oldString` anchor is kept). The authored
   * bytes are what hit disk; Model A's draft is discarded. Distinct from `model`,
   * which only swaps the model that PROCESSES the result on the next turn.
   * Honored only for mutating tools (write/edit) from TOOL-scoped decisions.
   * Omit ⇒ today's behavior (Model A's args are written as-is).
   */
  authorModel?: string;
  ```

- **`ToolContext`** (~line 239): add two optional fields
  ```ts
  /** Resolved authoring model (from decision.authorModel). When set on a
   *  write/edit call, the tool authors the bytes via `llm` instead of using
   *  the caller's draft. */
  authorModel?: Model;
  /** Context for an authoring pass: task, plan JSON, relevant surrounding
   *  file snippets. Populated by the runner only when authorModel is set. */
  authoringContext?: { task: string; planJson?: unknown[]; fileSnippets?: Array<{ path: string; content: string }> };
  ```

- **`ToolResult`** (locate in types.ts): add `usage?: Usage` so an internal LLM call's tokens are accounted in the chain total (currently only phase-model turns contribute usage at `phase-runner.ts:682`).

### 2. Phase runner — `src/orchestrator/phase-runner.ts`

In the decision block (~lines 954-983), after the existing `decision.model` handling:
- Resolve `decision.authorModel` (if present) to a `Model` via `llm.resolveModel`.
- Populate `toolCtx.authorModel` and `toolCtx.authoringContext` (built from `input.task`, `input.priorPlanJson`, and a bounded slice of `input.attachedFileContents` / `input.attachedContextFiles` — cap chars to keep the prompt lean, mirroring `MAX_SNAPSHOT_CONTEXT_CHARS`).
- Only do this for mutating write/edit calls (`mutates && (call.name === "write" || call.name === "edit")`).

After `tool.execute` (~line 988-997): if `res.usage`, accumulate `usage = addUsage(usage, res.usage)` so Model B's authoring tokens roll into the phase/chain total (and thus cost tracking).

### 3. Tools — `src/tools/builtin/coding.ts` (+ new helper `src/tools/builtin/authoring.ts`)

New helper module `authoring.ts` exporting:
- `authorFileContent(opts: { llm, model, path, task, planJson?, fileSnippets?, signal? }): Promise<{ content: string; usage: Usage }>` — builds a self-contained `Context` (system: "Produce ONLY the raw file contents, no markdown fences, no commentary"; user: task + plan + path + surrounding snippets), calls `llm.complete(model, ctx, { temperature: 0, signal })`, strips any accidental ```` ``` ```` fences, returns text + usage. Mirrors `ui-screen-auditor.ts:116-128` shape.
- `authorEditReplacement(opts: { llm, model, path, oldString, task, currentContent?, signal? }): Promise<{ newString: string; usage: Usage }>` — same shape but the model produces the replacement for the anchored `oldString`, given the current file content.

In `writeTool.execute` (`coding.ts:581-606`) and `editTool.execute` (`:624-657`): at the top, if `ctx.authorModel && ctx.llm`, call the helper and substitute the authored `content` / `newString` before the existing `fs.writeFile` path. On authoring failure (no bridge, endpoint error, empty output), return `isError: true` with a clear message + preserve Model A's draft in `details.draft` for diagnostics — never silently fall back to Model A's bytes, since the contract is "B authors". Return the helper's `usage` on the `ToolResult` so the runner accounts it.

### 5. Tests — `tests/` (new file `tests/authoring.test.mjs`)

Mirror the `runPrepareWithDecision` scaffold from `tests/multiplan.test.mjs:325-375` (custom `PermissionGate` with a callback returning a decision; stubbed `OpenRouterBridge` whose `complete` returns distinguishable content). Cases:
1. **write + authorModel**: callback returns `{ allowed: true, authorModel: "model-b" }`; stub Model B's `complete` to return `"B'S CONTENT"`. Assert the file on disk equals `"B'S CONTENT"` (NOT Model A's `args.content`).
2. **edit + authorModel**: Model A's `oldString` anchor is preserved; Model B authors `newString`; assert the replaced region equals B's output and the anchor matched.
3. **usage accounting**: assert the phase `usage.output` includes Model B's authoring tokens (proves the tool→runner usage propagation).
4. **backward-compat**: `decision.model` (without `authorModel`) on a write still writes Model A's content and only swaps the next turn's driver — assert disk has Model A's bytes.
5. **read unaffected**: `decision.model` on a read still means "B processes result" (no authoring).

## Out of scope (noted, not done)

- Streaming Model B's authoring to the host UI (v1 uses `complete()`; the diff is still rendered post-hoc via the tool result's `details`, as today). Can add `llm.stream` later.
- Applying `authorModel` to non-write/edit mutating tools (e.g. `bash`). The plan gates on `write`/`edit` only; generalizing later is a small extension of the same hook.

## Risk / invariant check

- Runner still does no content reasoning — it only resolves a slug, passes context, and accumulates usage. The LLM call lives in the tool. ✓
- Fully opt-in: `authorModel` absent ⇒ byte-identical behavior to today. Existing tests (`handoff`, `multiplan`, `file-memory`, `graph-memory`) install no `authorModel`, so they're unaffected. ✓
- Cost visibility: Model B's tokens are accounted via the new `ToolResult.usage` → runner accumulation, so chain `usage`/`cost` stays honest. ✓

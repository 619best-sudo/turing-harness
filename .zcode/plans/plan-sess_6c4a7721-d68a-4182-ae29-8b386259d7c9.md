# Make the chat UI smooth end-to-end (OpenWaggleMain)

## Diagnosis — where the frame budget goes

**While streaming (the lag you feel):** every single token delta travels main→renderer as its own IPC message, with **zero batching** (`stream-bridge.ts:41`). Each one then:
- costs **2 unconditional `logger.info` lines** (JSON.stringify + console) in the turing mapper (`turing-event-mapper.ts:79-99`) — always on at info level;
- re-concatenates the **full accumulated text** + copies the parts array in the main-side stream buffer — O(n²) over a message (`stream-buffer.ts:27-41`);
- in the renderer is **reduced twice**: once by the chat pipeline (`useAgentChat.message-cache.ts:74-119`) and *again* by `useBackgroundRunMonitor.applyRunRenderEvent` over a full transcript copy (`useBackgroundRunMonitor.ts:40-45` + `background-run-store.ts:67-80`) — 2 zustand sets + 2 Map/array copies per token;
- triggers O(transcript) row rebuilds (`buildChatRows`, `resolveTranscriptMessages`, `useWaggleMetadataLookup`) and — regression from the earlier fix round — `AssistantMessageBubble.renderableParts` **re-JSON.parses full tool args every tick** (`AssistantMessageBubble.tsx:783`), and `StreamingText` lost its `memo` (relies on React Compiler bailing).

**At run end (the choppy freeze):** the transcript is hydrated by `sessionToUIMessages`, which **replaces every message/part reference** — defeating all row memoization, re-parsing all completed markdown, re-rendering every file/diff view. It fires **2-3×** (double flush in `useBackgroundRunMonitor.refreshSession` + `flushDeferredSessionSnapshot`, plus a mid-stream hydration on first-run title assignment). Meanwhile the main thread runs the **synchronous full-projection DELETE+INSERT snapshot** (better-sqlite3, WAL with default `synchronous=FULL`), and `sessions:list` runs a **correlated COUNT over session_nodes per session** against the 96MB DB — all exactly when the UI rehydrates.

Also: your half-finished `agent-event-bus.ts` (batched `agent:event-batch`) was the right idea — it's unused and its IPC channel doesn't exist. This plan finishes that design.

## Fixes

### A. Main process — event pipeline (biggest win)
1. **Batch `agent:event` → `agent:event-batch`** in `emitTransportEvent` (`stream-bridge.ts`): buffer events for a 16ms window, flush as one array; flush immediately on lifecycle events (`agent_end`, errors) so completions never wait. Add the channel to `src/shared/types/ipc.ts`, expose `onAgentEventBatch` in `src/preload/api.ts` (keep `onAgentEvent` for remaining consumers). Expected 10-50× fewer IPC messages.
2. **Demote the per-event mapper logs to `debug`** (`turing-event-mapper.ts:79-99`).
3. **Fix the O(n²) stream buffer** (`stream-buffer.ts`): mutate the owned tail part in place instead of re-concatenating + array-copying per delta; drop the redundant `toJsonValue` deep-clone of tool results (IPC structured-clones anyway).
4. **SQLite pragmas** (`database-service.ts:96`): `synchronous=NORMAL` (WAL-safe), `wal_autocheckpoint=4000` — removes per-commit fsync stalls.

### B. Renderer — per-tick work
5. **One reduction per batch**: `useAgentEventEffects` + `useBackgroundRunMonitor` subscribe to `onAgentEventBatch` and apply the whole array in a single state commit (one `setMessagesForSession`, one store update).
6. **Kill the duplicate reduction**: the background monitor reduces only sessions the active chat pipeline is NOT driving — single ownership per session.
7. **Cache tool-args parsing**: `parsePathFromArgs` results in a `WeakMap` keyed by the (stable) part object — no per-tick `JSON.parse` of multi-KB args.
8. **Restore `memo` on `StreamingText`** and keep the incremental-markdown prefix cache after completion (don't discard) so completed parts stay cheap.
9. **Stop the 1s phase ticker invalidating row-building** (`useStreamingPhase.ts:198-212` → `useChatRows.ts:63-67`): elapsed time goes only to the phase-indicator row.

### C. Hydration / end-of-run
10. **One completion hydrate**: remove the duplicate flush (keep `flushDeferredSessionSnapshot`, drop the monitor's redundant `refreshSession` path for the same data).
11. **Identity-stable `sessionToUIMessages`**: reuse previous message/part objects when content is unchanged (keyed by node id + content hash) so reference equality survives hydration — rows bail out, no full-transcript re-render. This restores the protection the earlier fix round had at the comparator layer, at the correct layer.
12. **De-amplify `sessions:list`**: replace the correlated per-session `COUNT(*)` over session_nodes with a denormalized `node_count` on `sessions` (maintained in `persist-snapshot`) or an in-memory cache invalidated per-session-write.

### D. Verification
- `typecheck:web` + `typecheck:node` clean; run the affected unit + component suites (chat hooks, tool blocks, stores — the same ones green today; the 4 pre-existing `WaggleSection` failures are unrelated and untouched).
- Smoke criteria for you: a tool-heavy stream stays interactive (typing/scroll during tokens), no freeze at run completion, sidebar refresh doesn't hitch.

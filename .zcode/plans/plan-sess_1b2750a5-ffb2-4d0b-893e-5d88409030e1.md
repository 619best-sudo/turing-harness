# Explicit MCP selection + surface-locked QA hops (web XOR mobile)

## Context

Field runs showed the inspect hop opening with ~62 tools: 16 hop builtins + ~40 browser tools from the chrome-devtools/playwright MCP servers, auto-scoped into `activity_inspect` by name heuristics (registry/categorize.ts:110) merely because the servers were *enabled in settings*. On a Flutter/iOS project those browser tools were dead weight and actively misled the model ("my connected automation is browser-based"). Decisions (user):

1. Composer-selected MCPs join **all** categories; unselected MCPs join **none**.
2. `activity_inspect`/`activity_reproduce` carry **either web or mobile tools** — never both — by project category.
3. Replace the playwright-MCP dependency for web driving with our own first-party tool, like we did for `mobile`.

Key discovery: `drive` (src/tools/builtin/drive.ts) **already exists** as the web twin of `mobile` — same action API (`open/look/click/fill/select/press/shot/close`, text-first target resolution) — but it is a façade that resolves Playwright-MCP `browser_*` tools from the registry (drive.ts:49-75). Making it self-contained is item 3.

## Part 1 — Self-contained `drive` (turing-harness)

- `npm i playwright-core` — **lazy-imported** exactly like jimp, preserving the zero-hard-dependency contract; a host without it keeps the current MCP-façade behavior (fallback path).
- New `src/tools/web-session.ts`: per-cwd browser session singleton. Launch chromium (headless, system-Chrome channel first, bundled chromium second); `connectOverCDP` if a CDP endpoint env is set. Test seam mirroring mobilecli.ts: `setWebSessionOverride()` / `webSessionAvailable()`.
- Rewrite `drive.ts` actions to drive the session directly: goto, accessibility snapshot parsed into the SAME SnapElement format (so target resolution code is unchanged), click/fill/selectOption/press, screenshot. **Tool schema unchanged** (`action/url/target/text/value/key`) — zero prompt churn across prompts.ts/guidance.ts/chain.ts.
- Honest unavailability: if no browser and no playwright-core, the tool errors with the install/CDP instructions (mobile-tool precedent).
- Run-end cleanup: close the session where mobile sessions are closed today (chain cleanup pass).

## Part 2 — MCP chain-inclusion becomes selection-driven (turing-harness)

- `registry.add`: providers with `kind === "mcp" && source === "external"` default to `categorizers: []` — connected ≠ in-chain. Builtin providers unaffected (they're named in `def.tools`/`globalTools` anyway).
- New `Session.selectMcpServers(names: string[])`: scopes each named provider to **all** categories (`conversation, read, write_edit, activity_inspect`; `activity_reproduce` inherits via its `toolScope`). Re-callable per run; unlisted providers drop out.
- Back-compat escape: `includeUnselectedMcpTools?: boolean` session option (default false) restores today's auto-scope for other hosts.
- registry/categorize.ts heuristics stop applying to external MCPs (they only ever computed *where*, now selection decides *whether*).

## Part 3 — QA hops carry web XOR mobile (turing-harness)

- Stamp `providerId?: string` on `AgentTool` (types.ts; set in registry.add and mcp client/runtime-pool) so gating can identify origin reliably.
- In `resolveCategorizerTools` (chain.ts:180-254), for QA hops (`def.id`/`toolScope === "activity_inspect"`) using existing `input.projectCategory` (already threaded from `effectiveCategory()`/.turing/project.json):
  - `mobile` / `games` → drop `drive` + all browser-MCP tools
  - `frontend` → drop `mobile` + device-MCP tools
  - `backend` → drop both
  - Escape hatch: task text contains `https?://` → web surface wins (keep `drive`/browser tools) regardless of category
  - Explicit composer selection does **not** override this — selected MCPs ride the other three categories but the QA surface rule is absolute.
- Extend the existing `categorizer:tools` log (chain.ts:230-236) with `{dropped: [{tool, reason}]}`.
- QA-hop opener note via `forCategory` (prompts.ts): "This is a {mobile|web} project — your automation surface is {the device toolkit (`mobile`) | the browser (`drive`)}; the other surface's tools are not in this hop by design." Kills the bbd603ed "my automation is browser-based" misread.

## Part 4 — Composer picker + plumbing (OpenWaggleMain)

- `shared/types/agent.ts`: `AgentSendPayload.mcpServers?: string[]`; update `agentSendPayloadSchema` (validation.ts strips unknown fields — must be declared).
- Renderer: MCP picker in the composer (menu beside the attachments control) listing enabled stdio servers from `api.getMcpSettings()`; multi-select chips; `mcpServers: string[]` in ComposerState; included in `api.sendMessage`.
- Main: agent-handler → preflight → kernel → `runTuringSession`: after `connectMcpBackground` (which still connects all enabled servers into the warm pool — connection ≠ inclusion), call `turingSession.selectMcpServers(payload.mcpServers ?? [])` before the run starts.
- `turing_bridge_status` event gains `selectedMcpNames`. Runtime-cache signature unchanged (pool identical; scoping is per-run).

## Part 5 — Tests

- turing-harness: extend `tests/drive.test.mjs` (self-contained path via session override; façade fallback keeps existing cases green); extend `tests/category-leaks.test.mjs` + `tests/qa-two-roles.test.mjs` (or new `qa-surface-gating.test.mjs`): mobile→no drive/browser; frontend→no mobile; backend→neither; task-URL escape; selected MCP in all hops but stripped from mismatched QA hop; unselected external MCP absent everywhere; `includeUnselectedMcpTools` restores; `categorizer:tools` log carries drops.
- OpenWaggleMain: bridge unit test (selection threads to `selectMcpServers`); payload schema test; composer picker component test per existing vitest setups.

## Order & risk notes

Parts 1→2→3 land independently in turing-harness (each shippable, `dist` auto-picked-up via the `link:`), then Part 4. Risks: playwright-core adds ~8MB (no browsers bundled; system Chrome used first — mobile-style availability check errors honestly otherwise); behavior change for hosts relying on auto-scoped MCPs is gated behind the default-off flag.
